# 사이트 점검 보고서

점검일: 2026-09-30 · 대상: 게시된 www.smilesnail.org 메뉴 9개 페이지의 HTML 임베드 23개(데스크톱 14개, 모바일 9개)

전체 항목 목록은 [audit-findings.md](audit-findings.md)에, 같은 내용의 데이터는 [audit-findings.json](audit-findings.json)에 있습니다.

## 한눈에 보기

확인된 문제는 **143건**입니다(높음 13, 중간 60, 낮음 70). 사이트가 멈추거나 전체가 깨지는 수준의 문제는 없습니다.

방문자가 지금 바로 겪는 문제는 다섯 가지입니다.

1. **목록 뒷부분이 잘려서 볼 수 없습니다.** 데스크톱 Research의 특허 목록은 80건 중 뒤쪽 22건이, 데스크톱 Basic Lab의 논문 목록은 41편 중 13편이 보이지 않습니다. 아코디언의 최대 높이가 3,000px, 5,000px으로 고정되어 있기 때문입니다.
2. **펼치면 스크롤바가 하나 더 생깁니다.** 아코디언이나 '더보기'를 열면 내용이 고정 높이 iframe을 넘칩니다. 방문자는 페이지 스크롤 안에서 또 스크롤해야 합니다. Research는 3,843px 칸에 내용이 최대 32,664px까지 늘어납니다.
3. **페이지끼리 숫자와 목록이 안 맞습니다.** 홈은 "118 Journals"인데 Research 목록은 120편입니다. Research에 있는 Hearing Lab 2026년 논문 2편이 Hearing Lab 페이지에는 없습니다.
4. **검색결과와 브라우저 탭 제목이 템플릿 문구 그대로입니다.** 홈은 "건강 | 청각재활연구소", 연락처는 "문의 | BUSINESS NAME"입니다. 카카오톡이나 페이스북으로 공유할 때도 이 제목이 나옵니다.
5. **모바일은 별도 사본이라 내용이 다릅니다.** 9개 페이지 모두 데스크톱과 차이가 있습니다. 예를 들어 모바일 홈에는 소개 영상, 연구소장 이메일, 소속 한 줄이 빠져 있습니다.

원인은 대부분 구조에서 옵니다.

- Wix의 HTML iframe 요소는 높이를 코드로 바꿀 수 없습니다.
- 같은 내용을 여러 파일에 손으로 복사해 두었습니다. 논문 1편을 추가하려면 파일 6개(Research와 해당 연구실의 데스크톱·모바일, 홈 숫자 2곳)를 고쳐야 합니다. 서로 다른 논문·발표·특허 294건이 파일들에 742번 복사되어 있습니다.

### 1-C. 속도와 안정성

- **사진이 imgur 무료 호스팅에 있습니다.** 59장, 10.9MB입니다.
  - People 페이지는 90px 원형 사진 31장을 보여 주려고 원본 7.3MB를 받습니다. 가장 큰 사진은 1장에 1MB입니다.
  - imgur는 영국 접속을 막고 있어(검증 단계에서 영국 노드로 확인), 영국 방문자에게는 사진이 모두 깨져 보입니다.
  - 표시 크기에 맞게 줄여서 Wix 미디어나 이 저장소(GitHub Pages)로 옮기면 두 문제가 함께 풀립니다.
- **글꼴을 통째로 받습니다.** 임베드마다 Pretendard 전체 글꼴을 받아, 짧은 페이지도 글꼴만 1.5~3MB입니다. CSS 주소를 필요한 글자만 받는 dynamic-subset 판으로 한 줄 바꾸면 크게 줄어듭니다.

## 2. 구조 문제와 제안

### Wix에서 되는 것과 안 되는 것 (공식 문서로 확인)

| 질문 | 답 |
|---|---|
| HTML iframe 요소의 높이를 코드로 바꿀 수 있나? | **안 됩니다.** Velo HtmlComponent API에는 높이 관련 속성이 없습니다. iframe 안에서 높이 값을 보낼 수는 있어도 적용할 방법이 없습니다. |
| Custom Element는? | **게시된 사이트에서 내용만큼 커집니다.** 에디터에서 정한 높이는 최소 높이로 쓰입니다. 라이브에서는 iframe이 아니라 페이지에 직접 붙습니다. 조건(프리미엄 플랜, 도메인 연결, 광고 없음)은 이미 충족합니다. 단, 플랜이 끊기면 그 자리가 통째로 비게 됩니다. |
| 데스크톱 요소를 모바일에도 그대로 보여줄 수 있나? | **됩니다.** 지금은 데스크톱 요소를 모바일에서 숨기고, 모바일 전용 `#mobileHtml1`을 따로 둔 구조입니다. |
| Wix Git Integration을 쓰면? | 새 저장소만 만들 수 있고 WIX_DEV는 연결할 수 없습니다. 연결하면 에디터의 코드가 읽기 전용이 됩니다. **HTML iframe 안의 코드는 동기화 대상이 아닙니다.** |
| iframe '웹사이트 주소' 모드로 GitHub Pages를 띄우면? | 됩니다. push하면 약 10분 안에 재게시 없이 반영됩니다. 하지만 높이 고정 문제는 그대로입니다. |
| 기타 | 이 사이트는 클래식 Wix Editor입니다. Wix가 2025년 12월 도입한 프런트엔드 보안 조치로 iframe `srcdoc` 등이 막혀 있어, 옮기는 방식에 제약이 있습니다. |

각 항목의 원문 인용과 링크는 [wix-platform-facts.md](wix-platform-facts.md)에 있습니다.

### 제안: 세 단계

**1단계 (지금): 현재 방식을 유지하고 1장의 문제만 고칩니다.**
붙여넣기 방식은 그대로 두고, 잘림·누락·설정 문제를 먼저 없앱니다.

**2단계: 데이터를 한 곳에서 관리합니다.**
- 논문, 발표, 특허, 구성원을 `data/*.json` 한 곳에 두고, 스크립트가 23개 임베드 파일을 만들어 내게 합니다.
- 논문 1편 추가는 JSON 한 줄 추가로 끝나고, 바뀐 파일만 Wix에 붙여넣으면 됩니다.
- 데스크톱과 모바일, 페이지와 페이지 사이의 불일치가 구조적으로 생기지 않습니다.
- 이 단계는 3단계를 하든 안 하든 쓸모가 있습니다.

**3단계 (시범 후 결정): Research 한 페이지를 Custom Element로 바꿔 봅니다.**
- 성공하면 높이 문제, 모바일 사본, 붙여넣기가 한꺼번에 사라집니다. 코드는 GitHub Pages에서 불러옵니다.
- 시범에서 확인할 것:
  1. 라이브에서 높이가 자동으로 맞는지
  2. 모바일 320px 화면에서 하나로 충분한지
  3. 2025년 12월 보안 조치의 영향이 없는지
  4. 에디터 미리보기가 실제와 다르게 보이는 점을 감당할 수 있는지
- 감수할 위험: 프리미엄 플랜에 의존하게 되고, 저장소 내용이 공개됩니다(지금도 public).

권하지 않는 방법:
- 대시보드 Custom Code로 iframe 높이를 강제로 바꾸는 비공식 우회법. 아래 요소가 밀리지 않는다는 보고가 있습니다.
- Wix Git Integration. 새 저장소가 강제되고 에디터 코드가 읽기 전용이 되는데, 이 사이트에서 얻는 이점은 적습니다.

## 5. 점검 방법과 한계

- 게시된 사이트에서 23개 임베드 코드를 Wix 서버로부터 직접 내려받았습니다. 받은 데스크톱 14개는 붙여 주신 코드와 일치했습니다.
- 높이는 실제 사진과 글꼴을 내려받아 오프라인으로 렌더링해 측정했습니다. 실제 사이트를 브라우저로 여는 것은 이 환경에서 허용되지 않아 하지 못했습니다.
- 에이전트 12개가 페이지별·주제별로 점검했습니다. 이어서 다른 에이전트가 항목마다 파일을 다시 열어 반박을 시도했고, 145건 중 143건이 확인되고 2건은 반박되어 뺐습니다.
  - audiso.co.kr이 403을 낸다는 항목: 여러 나라 노드에서는 정상이라 지역별 차단으로 판단했습니다. 한국에서 한 번 눌러 확인해 주세요.
  - 연락처 이메일 링크의 명암비 항목: 기준을 잘못 적용한 것으로 판단했습니다.
- Wix 플랫폼 관련 사실 15개는 dev.wix.com, support.wix.com 원문과 라이브 사이트 코드로 확인했습니다.
- 이 보고서의 핵심 숫자(120편, 80건 중 동일 항목 6쌍, Hearing Lab 누락 2편, 아코디언 최대 높이)는 따로 다시 세어 확인했습니다. 부록의 개별 항목 수치와 다르면 이 보고서가 우선합니다.
