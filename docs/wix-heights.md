# Wix HTML 요소 높이 (3차, C2 디자인)

Wix HTML 요소는 내용에 맞춰 높이가 바뀌지 않는다. **쪽의 내용 길이가 바뀌면(학회 발표·논문·특허·구성원·사진을 더하거나 문구를 고치면) 이 표를 다시 재고, Wix 에디터에서 그 요소의 높이만 고친다.** 높이가 모자라면 쪽 아래가 잘리고, 남으면 아래가 빈다.

## 재는 법 (저장소 루트)

```
python3 tools/build.py
node tools/verify/heights.js site/home.html site/about.html ... --md      # 폭 980·1100·1280·1440·1920 + 320, KO·EN
node tools/verify/heights.js site/gallery.html --sweep 20 --md           # 사진 줄이 있는 갤러리: 980~1920을 20px마다
```

- heights.js는 쪽마다 폭과 언어를 바꿔 새로 열고, 글꼴이 다 들어온 뒤(0.8초 더 기다림) 문서 높이를 잰다. 표의 값은 그 출력 그대로다(긴 언어 + 24px, 10 단위 올림).
- Home·About의 갤러리 맛보기는 장수가 정해진 줄(2 + 3장, 3장)이라 폭에 비례해 길어지므로 다섯 폭으로 충분하다. 갤러리 쪽(쪽당 12장을 줄로 나눔)만 `--sweep` 이 필요하다.
- 실제 Wix와 같은 조건(교차 출처, 바깥 쪽이 스크롤)의 확인은 `node tools/verify/wixsim.js site/<쪽>.html <out> --w 1280`(또 `--w 320`, `--lang en`)이다. 이번 빌드의 30회에서 1280 문서 높이는 KO = EN이었고, 320 문서 높이에 24px를 더해 올리면 10쪽 모두 위 표의 모바일 값과 같다(예: Research 9,206 → 9230).

## 언제 다시 재나

- **학회 발표·논문·특허를 더했을 때**(Research와 연구실 쪽): 목록은 '10줄 한 쪽' 가운데 가장 긴 쪽을 예약하므로 건수만으로는 거의 바뀌지 않지만, 제목·저자가 긴 항목이 들어오거나 새 연도가 생기면 바뀐다. 데이터를 합친 뒤에는 늘 다시 잰다(빌드와 heights.js 몇 분).
- **구성원을 더하거나 뺐을 때**(People, 연구실 쪽의 인원 링크): 팀의 줄 수가 바뀌면(데스크톱 6명, 320 3명마다 한 줄, 교수진은 3명·320 목록) 높이가 바뀐다.
- **사진을 더했을 때**(Gallery, Home·About 맛보기): 갤러리는 `tools/pages/gallery.md` 4절. 맛보기는 장수가 정해져 있어 사진 모양만 영향을 준다.
- **문구를 고쳤을 때**: 고친 쪽.
- 다시 잰 값이 지금 Wix에 넣은 값보다 크면 반드시 고친다(잘림). 작으면 고치지 않아도 잘리지는 않는다(아래가 조금 빈다).

이전 값(같은 날 마무리 전 빌드: home 4900 / 5400, research 6000 / 9200, audiso 3320(980 2880) / 4550 등)은 이 표로 바뀌었다. 2차 디자인의 높이(참고, 지금 게시된 값이 아니다)는 `tools/KIT_v2.md` 끝의 표에 있다.
