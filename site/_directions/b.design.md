# B · 클리니컬 모던 · 디자인 문서

원본: `tools/kits/b.py`(페이지 전체), `tools/kits/b/`(첫 화면: /67 최종안 `site/_directions/_67/b/final/` 을 복사. 바뀐 곳은 영상 데이터 예산 때문에 고친 영상 로더 하나(`hero.html` 안의 인라인 스크립트와 `hero.js` 두 줄, 아래 'Wix iframe 메모' 참고)와 리뷰 1 에서 장부 숫자에 붙인 화면낭독기용 최종값(`hero.html` 네 줄), 리뷰 2 에서 페이지와 같은 단계로 맞춘 `hero.css` 값 일곱 개(장부 라벨 상한 14 px, 320 축 숫자·판독값 10 px, 320 링크 14 px, 이름과 축 사이 최대 24 px, 320 위아래·소속·축·리드 여백 4 px 단계, `--gut` 하한 24 px, 일시정지 단추 오른쪽 12 px). 모양과 움직임은 그대로).
빌드: `python3 tools/directions.py b` → `site/_directions/b.html`. 다른 방향과는 `tools/core.py` 만 함께 쓴다.

## 방향 한 문장

청력도(오디오그램)의 주파수 축 125 Hz~8 kHz를 페이지의 격자로 삼고, 흰 바탕에 청록 한 색과 회색 머리선으로, 측정기처럼 정밀하게 보여 주는 병원·의료기기 계열의 산세리프 디자인.

## 모션 논지 (impeccable animate · delight, 구현 전에 적음)

방문자 모드: 첫 화면은 설득(Persuade), 논문 목록과 구성원은 읽기(Read). 그래서 공들인 장면은 첫 화면 하나에 두고, 읽는 구간의 움직임은 상태 변화를 알려 주는 데만 쓴다.

- **초점 장면 (하나)**: 첫 화면의 측정. 청록 커서 하나가 청력도 주파수 축(125 Hz~8 kHz)을 검사음처럼 훑고, 지나가는 옥타브마다 눈금과 숫자를 찍는다. 이름이 축에서 올라오고, 창(연구소 영상)과 글이 커서 뒤로 드러난다. /67 최종안 그대로.
- **같은 행위의 반복 (성과 띠)**: 같은 커서가 이번에는 시간 축(2008~2026년)을 훑는다. 커서가 지나간 해의 막대가 서고, 큰 숫자는 커서가 있는 해까지의 **누적 건수**다. 숫자가 올라가는 것이 곧 기록이 쌓이는 것이라서, 카운트업이 장식이 아니라 데이터의 뜻이 된다. 특허는 등록(채운 칸)과 출원(빈 칸)이, 기술이전은 12칸이 같은 진행으로 켜진다. 첫 화면의 측정이 끝난 뒤에만 시작한다.
- **연속성 (읽는 구간)**: 논문 목록 위에 120편을 한 줄로 편 기록 지도(눈금 120개, 목록 순서)를 둔다. 필터를 고르면 해당 논문의 눈금이 청록으로 켜지고, 지금 보는 쪽의 10편 눈금이 올라선다. 쪽이나 필터를 바꾸면 새 목록이 첫 화면 글 단과 같은 부드러운 경계의 스캔으로 들어온다(0.42초). 120편 가운데 어디를 보고 있는지가 움직임으로 설명된다. 아래 쪽 넘김으로 바꿨는데 목록 머리가 화면 밖이면 목록 머리로 부드럽게 옮겨 간다.
- **구간 제목**: 각 구간의 이름은 첫 화면의 이름처럼 자기 아래 축에서 올라온다(SplitText 줄 단위, 마스크). 축 선은 왼쪽에서 오른쪽으로 그어진다.
- **구성원 사진**: 사진은 첫 화면의 창과 같은 재료다. 기준선에서 위로 열리며(clip-path) 초점이 맞듯 1.08배에서 1배로 가라앉는다. 그 뒤로는 움직이지 않는다(읽는 구간. 리뷰 2 에서 스크롤 연동 깊이 효과를 뺐다). 사진에는 링크가 없으므로 호버 반응을 주지 않는다.
- **피드백**: 필터 단추, 쪽 넘김 단추, 첫 화면 링크, 일시정지 단추만 손에 반응한다(100~350 ms). 필터 단추 옆 숫자는 다른 필터와 겹친 실제 건수라서, 빈 결과로 가기 전에 알 수 있다.
- **기쁨 논지 (한 문장)**: "기록을 만지면 측정기가 답한다". 성과 막대 위에 포인터를 올리면 첫 화면과 같은 커서와 판독값이 그해의 건수(예: 2020 · 17)를 보여 주고, 목록에서는 기록 지도가 필터와 쪽에 맞춰 켜진다. 둘 다 데이터에서 나온 실제 값이고 새 문구가 없다.
- **예산**: 반복은 첫 화면 영상 하나뿐(화면 밖·탭 숨김·일시정지 단추에서 멈춤). 나머지는 한 번만 돈다. 스크롤 연동 깊이 효과는 첫 화면 창 하나, 데스크톱만, transform만 바꾼다(gsap.quickTo). WebGL·캔버스 없음.
- **동작 줄이기**: `html.rm` 이면 처음부터 최종 상태. 아무것도 움직이지 않고(호버 전환도 즉시), 영상은 정지 화면 한 장.

## 격자

- 폭: `min(1320px, 100% - 2 × pad)`, pad clamp(16px, 4.4vw, 64px). 1920에서도 1320에서 멈추고 가운데 놓인다.
- **6열 = 옥타브 6칸** (125, 250, 500, 1k, 2k, 4k, 8k Hz). 구간 단위로는 열 사이 간격 0이라서 모든 블록이 옥타브 선에서 시작한다. 글 단은 오른쪽 안쪽 여백(`--gut` clamp(24px, 2.5vw, 36px))으로 띄운다.
- 첫 화면: 이름 1~4열 · 성과 장부 5~6열 / 글 1~2열 · 창 3~6열.
- 성과 띠: 문장 1~2열 · 판독 칸 넷이 3, 4, 5, 6열. 칸 사이 세로선이 첫 화면 축의 500 Hz, 1k, 2k, 4k 눈금 위치와 같다.
- Research: 리드와 필터 1~2열 · 목록 3~6열(첫 화면 창과 같은 왼쪽 선).
- People: 사진 줄만 열 사이 간격(`--gut`)이 있는 6열. 교수는 2열씩(사진 1열 + 글 1열), 랩 구성원은 1열씩이라 교수 사진과 랩 사진이 같은 열에 선다. 간격이 있으므로 사진 왼쪽 선은 옥타브 선에서 열마다 gut/6 씩 밀린다(1440 에서 0/6/12/18/24/30 px). 바깥 두 선(축의 시작과 끝)을 지키려고 고른 것이다(리뷰 2 확인).
- 320: 한 단. 성과 칸은 2×2, 필터는 단추 격자(팀 2열, 연도 3열, '전체'는 한 줄 전체), 교수는 사진 92px + 글, 랩은 3열.

## 부품

- **이름과 축 (구간 머리)**: h2 + 1 px 축선(바탕 `--rule`, 그어지는 선 `--teal`). 보이는 언어의 글줄이 축 바로 위에 선다.
- **판독 칸 (성과)**: 라벨(두 줄 자리, 아래 맞춤) / 큰 숫자 / 그림 44px / 각주. 칸 오른쪽 안쪽 여백 clamp(10px, 1.1vw, 16px)로 그림이 옆 칸 선에 닿지 않는다. 세는 숫자는 aria-hidden 이고 최종값을 숨은 글자로 따로 둔다(첫 화면 장부도 같음). 그림은 데이터 종류마다 다르다.
  - 논문·학회 발표: 2008~2026년 막대(두 차트가 같은 연도 축, 같은 눈금 최대 19). 축 숫자는 첫 해, 2015, 마지막 해. 2015는 `core.SINCE`('2015년부터…')에서 읽고 청록으로 찍는다. 문장 속 2015도 같은 청록.
  - 특허: 한 칸이 특허 하나. 등록 37 = 채운 칸, 출원 43 = 빈 칸(청록 테두리). 범례는 숫자 먼저('37 등록').
  - 기술이전: 12칸(`core.TECH_TRANSFERS`, 1차 문구 값).
- **필터**: 데스크톱은 세로 목록(라벨 + 건수, 눌림 = 청록 1 px 세로선(그 값 위에 선 커서) + `--tint`), 320은 테두리 단추 격자(높이 40 px, 글자 13 px, 'Collab & Medical 41' 도 한 줄). 라벨과 건수는 기준선을 맞추고 줄은 단추 가운데(grid). 건수는 다른 필터와 겹친 실제 건수(0이면 라벨이 `--mute`). 호버 색은 `hover: hover` 기기에서만(폰에서 눌린 뒤 남지 않음).
- **쪽 넘김**: 36px(320은 40px) 사각 단추 둘 + '1 / 12'. 목록 위(고정 위치)와 마지막 행 바로 아래 두 곳. 화면낭독기에는 필터·쪽을 바꿀 때만 숨은 상태 줄이 '41건 · 1 / 5' 처럼 화면의 두 문자열을 읽는다(보이는 건수는 알림 영역이 아님).
- **기록 지도**: 논문 120편 = 눈금 120개(목록 순서, 왼쪽이 최신). 필터에 걸린 눈금 청록, 지금 쪽 10개는 두 배 높이 `--teal-2`. 아래 2025·2020·2015 경계 표시(오른쪽 끝 표시는 눈금 왼쪽에 매단다).
- **논문 행**: 연도·팀 | 제목 / 저자 / 학술지. 링크가 없으므로 호버 반응 없음. 빈 결과는 `core.UI['none']`.
- **팀 머리**: h3 + 인원 숫자. 숫자는 언어별 이름 안에 들어 있어 보이는 이름 바로 뒤 8 px 에 선다(두 언어 겹침 칸 밖에 두면 긴 쪽 이름 폭만큼 떨어졌다). 숫자는 aria-hidden(목록이 항목 수를 알린다).
- **사진 액자**: 4:5, 모서리 2 px, 안쪽 1 px 선. 사진 층은 액자와 같은 크기(리뷰 2 에서 깊이 이동과 함께 6% 여유를 뺌, 얼굴 위치 차이 1~2 px). 사진이 없는 구성원은 같은 액자에 성의 첫 글자(`core.initials`). 전신 스냅 두 장(김진수, 서연호)은 얼굴이 다른 사진과 같은 높이에 오도록 원본으로 확대해 자른다(데이터가 아닌 표시 설정, `FOCUS`).
- **KO/EN 한 칸 겹침 (`.b-d`)**: 두 언어를 한 격자 칸에 겹쳐 두고 안 쓰는 쪽을 `visibility: hidden` 으로 숨긴다. 상자가 두 언어 중 큰 쪽이라 언어를 바꿔도 줄바꿈·높이가 그대로다. 이름과 역할은 줄마다가 아니라 언어별 덩어리로 겹친다.

## Wix iframe 메모

- vh·svh·dvh·innerHeight, fixed·sticky, wheel·touch preventDefault, 창 스크롤 ScrollTrigger 없음. 첫 화면 높이는 px·vw와 aspect-ratio로만(폰은 556px 고정).
- **높이가 언어와 클릭에 상관없이 하나**: 목록은 core 엔진이 가장 긴 쪽을 예약하고, kit 가 그 예약을 목록을 감싼 상자로 옮겨 아래 쪽 넘김이 마지막 행 바로 아래 온다. KO/EN 은 한 칸 겹침으로 같은 높이. 시안 표시 띠(core)는 한글 글자가 고정폭 글꼴 안에서 더 큰 대체 글꼴을 써서 1 px 커지므로 이 페이지에서 60px로 고정했다.
- **core 센티널 상자 문제와 kit 쪽 대응**: core 는 `#rihe-band` 를 웹 글꼴이 오기 전 문서 높이로 한 번 만들고, 문서가 커질 때만 다시 만든다. 글꼴이 오며 내용이 줄면(이 페이지는 1280에서 3826 → 3778) 상자가 문서를 47px 더 길게 붙잡아 Wix 요소 안에 스크롤이 생길 수 있다. kit CSS 에서 `body { position: relative }` + `#rihe-band { max-height: 100%; overflow: hidden }` 으로 상자를 본문 높이에 묶었다(띠 오차 0.5 px 유지). core 에서 고치면(문서 높이를 잴 때 상자 자신을 빼기) 이 두 줄은 필요 없다.
- 폰에서는 띠를 쓰는 효과가 없어서 띠를 시작하지 않는다(센티널 비용 0). 그래서 wixsim 320 의 band 값은 문서 높이와 같게 나온다(첫 화면 /67 판정과 같은 이유).
- 사진·영상은 Wix 미디어와 Imgur 주소를 그대로 쓴다(Imgur 대소문자 유지, 크기 접미사만 `core.imgur`). 사진은 `loading="lazy"`.
- **영상 데이터 예산 (CLAUDE.md, 2026-11-06 추가 규칙)**: 첫 화면 영상은 21.2MB 홍보영상의 112.05~116.42초 구간이다. /67 최종안처럼 파일 주소를 그대로 재생하면 브라우저가 재생 위치부터 약 36초를 미리 받아 처음 1초에 5.11MB가 나갔다(목표 10초에 3MB 이하). 그래서 첫 화면 인라인 로더가 range 요청 두 번으로 필요한 바이트만 받는다: 앞 512KB(ftyp, moov 색인, 첫 샘플)와, 색인에서 계산한 111.4~119초 구간(직전 키프레임부터, 약 0.92MB). 둘을 파일과 같은 배치의 Blob(사이는 읽히지 않는 0, Blob은 구간 끝에서 끝남, 메모리 약 11.6MB)으로 만들어 `#t=112.2` 로 재생한다. 측정: 처음 12초 동안 영상 전송 1.71MB(CDP encoded 합계, 실제 본문 약 1.45MB), 그 뒤 추가 전송 없음, 반복 112.3 → 116.3 → 112.7 정상. range 응답이 206이 아니거나 색인이 예상과 다르거나 Blob 재생이 오류면 파일 주소로 되돌아간다(예산은 넘지만 화면은 같다). 동작 줄이기는 같은 클립에서 112.2초 정지 화면 한 장, 폰·Save-Data·2g·3g는 아무것도 받지 않는다(사진). 플레이어는 하나.
- 페이지 사이 링크는 첫 화면의 `/project` 하나(target _top). 영어에서는 core 가 `/en/project` 로 바꾸는데 Wix Multilingual 이 꺼져 있어 지금은 404다(core 동작).

## 열린 문제

### 구체성 판정

이 제품만을 위해 만든 화면이다. 청력도 주파수 축(125 Hz~8 kHz)이 격자이고 모든 블록이 옥타브 선에서 시작하며, 움직임은 '측정하는 청록 커서' 하나다. 성과는 실제 논문·발표의 연도별 막대, 특허의 등록/출원 칸, 이전 12칸으로 숫자 뒤의 기록을 보여 준다. 흰 바탕·청록·머리선은 의료기기 계열의 흔한 옷이지만, 축 개념과 연구소 자신의 청력검사 영상이 다른 제품이 그대로 가져다 쓸 수 없게 만든다.
검출기(`impeccable detect`, 경고 30): 18개는 첫 화면 축 숫자(1 px 청록 눈금의 자식이라 배경을 청록으로 오인, 실제는 흰 바탕), 4개는 첫 화면 장부 행이 자기 선 위에 앉은 설계, 2개는 320 성과 칸이 본문 왼쪽 선에 맞춘 설계, 1개는 core 시안 표시 띠의 회색(평가 대상 아님), 5개는 320 첫 화면 장부 라벨 10px(실제 문제, 아래 P3). 검출기는 영문 인원 간격, 차트가 옆 칸 선에 닿는 것, 알림 영역 문제, 반대 방향 시간 축은 잡지 못했다.
